# 技术与模型决策

## 先建立可信资料，再讨论复杂流程

来源与用途由程序过滤，不能只在提示词里要求模型保密。聊天中产生候选后，由本人核对并确认；生成前读取当前版本与当前许可。模型只处理被允许的资料，不能自行扩大权限。

| 方案 | 做什么 | 采用条件 |
| --- | --- | --- |
| T0完整授权资料 | 把当前允许使用的短资料全部交给模型 | 当前资料短且需要容易核对，因此为应用默认 |
| T1固定RAG | 过滤权限和版本，再用BGE向量表示与检索选片段 | 资料增长，完整输入成本或上下文干扰成为实际问题时再比较 |
| 受限单Agent | 模型选择读取、来源核对、澄清或结束，程序执行有限工具 | 任务需要不同处理分支，收益足以覆盖额外调用与不确定性时 |

BGE是本地文本向量模型，不负责生成回复。检索本身不必调用在线生成模型。相关片段仍可能缺少问题所需的日期、对象或条件，也可能检索错位，因此“检到了”不等于“答得出”。

Agent有时需要两次生成模型调用：第一次选择工具，此时没有工具结果；工具执行后，第二次据此回答。直接澄清或结束可以一次完成。T0/T1是完整资料与固定RAG对照，不是普通调用与Agent对照。

## DeepSeek是实验基线，生产模型仍需比较

已有实验使用DeepSeek：中文短资料任务、结构化输出、接入成本和预算可控，同时保持生成模型一致，以比较资料策略。历史记录使用`deepseek-flash`请求名；不据此推断更精细的底层模型版本。没有完成多厂商择优。

真正开发前，先以事实与权限边界、数据处理条件作为门槛；通过后比较角色忠实、自然交流、延迟、稳定性、结构化输出、维护和有效会话成本。不能只按每百万token标价决定。

建议使用同一组输入、授权资料、输出限制，打乱模型名进行评价，区分开发集与留出集。2026.09.23本地方案提出30个合成场景（10聊天、8事实、6提取、6撤回）；这是待执行方案，不是已有样本结果。本公开包不预设某个候选模型胜出，也没有新增跨模型调用。

## 可选真实调用

默认模拟已足够检查界面流程。如自行测试真实适配，先核对服务商当前接口、模型名与费用，再运行：

```sh
python -X utf8 app/server.py --provider deepseek --model YOUR_VERIFIED_MODEL --max-calls 1 --db app/data/live-demo.sqlite3 --port 8771
```

`YOUR_VERIFIED_MODEL`需替换为已核对的模型名。启动时在终端隐藏输入Key，不放在命令行或前端。发送和整理会产生付费请求；失败也计入本地尝试上限，不自动重试。代码按当前演示设置关闭thinking、要求JSON，服务商接口变化时需重新核对适配。不要通过更换数据库绕过已经约定的验收预算。

本演示只监听回环地址，同一操作者可进入主人和访客视角；这些视角用于演示用途边界，不能当作生产账号隔离。公网服务需要另行设计身份、数据管理、并发与部署。
